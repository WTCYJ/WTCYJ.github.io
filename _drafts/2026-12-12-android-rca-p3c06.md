퍼징으로 크래시 하나를 건졌다고 치자(2부의 퍼징). 손에 쥔 건 보통 수 KB짜리 입력 파일이고, 그중 결함을 실제로 건드리는 바이트는 몇 개뿐이다. 나머지는 파서가 여기까지 오도록 만든 배경 잡음이다. 이 상태로는 "왜 터지는가"를 말할 수 없다. 근본원인은 살아남은 바이트가 어느 필드에 대응하는지 보일 때 드러난다. 그래서 RCA의 첫 손질은 **입력 축소**다 — 같은 곳에서 같은 방식으로 터지는, 더는 줄일 수 없는 입력으로 깎아내는 일.

이 글은 델타 디버깅(ddmin)과 `afl-tmin`으로 자작 파서의 크래시 입력을 최소화하고, 그 과정에서 반드시 지켜야 하는 불변량 — 폴트 사이트 보존 — 을 형식화한 기록이다. 축소는 예뻐 보이려는 작업이 아니라, 취약 필드를 노출시켜 근본원인을 특정하는 분석 단계다.

> **한 줄 결론**: 입력 축소의 불변량은 "크래시한다"가 아니라 **"같은 폴트 사이트에서 크래시한다"**다. 이 조건을 오라클에 넣지 않으면 리듀서는 최소 입력이 아니라 *다른 버그*로 수렴한다.

## 무엇을 다루고, 무엇을 알아야 하는가

이 글은 크래시 입력을 최소 재현으로 줄이는 방법론을 다룬다. 델타 디버깅의 ddmin 알고리즘, `afl-tmin`의 실전 사용, 결정론적 오라클의 조건, 그리고 입력 리듀서와 소스 리듀서의 구분이다. 대상은 자작 JNI 파서와 이미 패치된 공개 CVE의 재현물뿐이다.

선수 지식이 셋 깔린다. 3부 1장의 **증상/트리거/폴트 사이트/근본원인 구분** — 축소가 보존해야 할 대상이 바로 "폴트 사이트"이므로 이 구분이 없으면 무엇을 지키는지 모른다. 3부 5장의 **baseline·patched·negative control** — 축소의 오라클은 결국 "이 입력이 결함을 재현하느냐"를 판정하는 대조 실험이다. 그리고 크래시 트라이아지(툼스톤/ASan 판독) — 두 크래시가 "같은 것"인지 판정하려면 폴트 사이트를 읽을 수 있어야 한다. 완화 배경은 Atlas C37을 참고하면 된다.

전체 구조에서 이 장은 RCA 파이프라인의 중간에 선다. 앞(1~5장)에서 결함을 재현하고 대조군을 세웠다면, 여기서 입력을 깎아 결함의 실체를 최소 형태로 고정하고, 다음 장(3부 7장)에서 그 크래시가 실제로 무엇을 할 수 있는지 — DoS냐 그 이상이냐 — 를 정직하게 산정한다.

## 핵심 개념 — 델타 디버깅과 1-minimal

델타 디버깅의 `ddmin`은 이진 탐색을 "집합"으로 일반화한 알고리즘이다. 실패하는 입력을 `n`개(처음 2개)로 쪼개, 각 부분과 각 여집합을 오라클에 통과시켜 본다. `Source-confirmed`

- 어떤 **부분**이 여전히 실패시키면 → 그 부분으로 좁히고 `n`을 2로 리셋
- 어떤 **여집합**이 여전히 실패시키면 → 여집합으로 좁히고 `n`을 하나 줄임
- 둘 다 아니면 → 입도를 높임(`n`을 2배)
- `n`이 남은 길이를 넘으면 종료

결과는 **1-minimal**이다: 남은 단위 중 어느 하나를 더 제거해도 실패가 사라지는 상태. `Source-confirmed` (Zeller & Hildebrandt) 여기서 흔한 오해 하나 — 1-minimal은 *전역 최소*가 아니다. "한 개씩 빼면 안 줄지만, 두 개를 동시에 빼면 더 줄 수도 있는" 국소 최소일 뿐이다. `afl-tmin`도 같은 성질의 국소 최소를 낸다. 최소 재현을 "이론상 가장 짧은 입력"으로 착각하면 안 된다.

오라클은 세 값을 낸다: 실패(✗, 우리가 원하는 결함), 통과(✓), 미해결(?, 파서가 다른 이유로 죽거나 hang). `ddmin`이 견고하려면 이 판정이 **결정론적**이어야 한다. 뒤에서 다룰 핵심 함정이 전부 여기서 나온다.

> **[그림 1]** 원본 크래시 입력을 `xxd crash-orig.bin | head`로 덤프한 터미널 — 수천 바이트 중 결함과 무관한 잡음이 대부분임을 보여주는 화면 — *실측 스크린샷 자리*

## 실습 환경과 안전 범위

전부 **호스트의 자작 파서 하네스**와 **AVD**로만 진행한다. 제3자 앱·실서비스·무기화된 익스플로잇은 없다. 축소의 산출물은 "최소 크래시 입력"까지이고, 그 입력이 무엇을 넘어 무엇을 할 수 있는지는 다음 장의 exploitability 산정으로 넘긴다.

대상은 자작 TLV 파서다. 길이 필드를 읽고 경계 검사 없이 `memcpy`하는, 교과서적 OOB 결함을 심어 두었다. 이 파서를 두 곳에서 돌린다 — (1) 호스트에서 `afl-clang-fast` + ASan으로 빌드한 하네스(축소·판정용), (2) 같은 코드를 JNI로 올린 AVD 앱(현장 재현 확인용). 축소 자체는 빠르고 결정론적인 호스트 하네스에서 한다.

## 실습 절차와 관측

### 가설
- **가설 A** — `afl-tmin`은 수 KB 입력을 십수 바이트로 줄이고, 살아남은(= `0x30`으로 치환하면 크래시가 사라지는) 바이트는 취약 길이 필드에 대응한다. `Inferred`
- **가설 B** — 폴트 사이트 검사를 오라클에 넣지 않으면(`AFL_TMIN_EXACT` 미설정), 최소 입력이 *다른* 크래시 위치로 새어갈 수 있다. `Inferred`

### 절차
1. 원본 크래시 입력이 하네스에서 결정론적으로 터지는지 N회 재확인한다(baseline).
2. `afl-tmin`으로 축소하되, 같은 위치 크래시만 인정하도록 `AFL_TMIN_EXACT=1`을 준다.
3. 최소 입력을 ASan 바이너리로 재실행해 폴트 사이트가 원본과 동일한지 대조한다.
4. `xxd`로 최소 입력을 덤프해 남은 바이트를 파서 구조 필드에 매핑한다.

```bash
# 하네스 빌드 (ASan 포함)
AFL_USE_ASAN=1 afl-clang-fast -g -o parse_harness harness.c parser.c

# baseline: 원본이 결정론적으로 터지는지 확인
for i in $(seq 1 20); do ./parse_harness crash-orig.bin >/dev/null 2>&1 || echo "crash $i"; done

# 폴트 사이트를 고정한 채 축소
AFL_TMIN_EXACT=1 afl-tmin -i crash-orig.bin -o crash-min.bin -- ./parse_harness @@

# 최소 입력 재실행 → 폴트 사이트 대조
./parse_harness crash-min.bin
xxd crash-min.bin
```

> **[그림 2]** `afl-tmin` 종료 배너의 크기 축소 통계(원본 → 최소 바이트)와, 최소 입력 재실행 시 원본과 동일한 ASan 폴트 사이트(`parser.c:NN heap-buffer-overflow`)를 다시 찍은 대조 캡처 — *실측 스크린샷 자리*

### 관측 결과

`예시 출력(교체)` — 아래 크기 축소 라인은 **개념 요약**이며 `afl-tmin`의 실제 종료 배너가 아니다. 실제 배너는 `File size reduced by : …%` · `Characters simplified : …%` · `Number of execs done : …` · `Fruitless execs : …` 형식으로 찍히므로, 네 실제 실행 출력으로 바꿔라:

```
# afl-tmin
[*] Read 4096 bytes from 'crash-orig.bin'.
[+] Program exits with a signal, minimizing in crash mode.
    ...
    Block normalization  : 4096 -> 24 bytes
    Alphabet minimization: 24 -> 3 bytes
[+] Done: 3 bytes remain.

# 최소 입력 재실행
$ ./parse_harness crash-min.bin
==12931==ERROR: AddressSanitizer: heap-buffer-overflow ... in parse_tlv parser.c:47

$ xxd crash-min.bin
00000000: 0102 ff                                  ...
```

원본 4096바이트가 3바이트로 줄었고, 폴트 사이트는 `parser.c:47`로 원본과 같다. 남은 3바이트는 `tag(0x01) · type(0x02) · length(0xff)`이고, 그중 결함을 만드는 건 세 번째 바이트 `0xff` — 경계 검사 없이 `memcpy` 길이로 쓰이는 필드다. `afl-tmin`은 알파벳/문자 최소화 단계에서 남은 자리를 NUL(`0x00`)이 아니라 ASCII `'0'`(`0x30`)으로 정규화하므로(결과물이 `0x30`으로 채워지는 잘 알려진 관측), 판정 기준은 "non-zero"가 아니라 "`0x30`으로 치환하면 크래시가 사라지는 = 결함 트리거에 필수적인 바이트"다. 즉 xxd 덤프에서 필러는 `0x00`이 아니라 `0x30`으로 찍히니, 그 필러가 아닌 값만 필수 바이트로 읽으면 된다. 축소가 끝나는 순간 근본원인의 위치와 트리거 조건이 동시에 눈에 들어온다.

## Root Cause — 왜 이렇게 되는가

축소가 근본원인을 드러내는 이유는 단순하다. 파서 입력의 대부분은 **결함까지 도달하기 위한 문맥**이고, 결함 자체를 결정하는 바이트는 소수다. 잡음을 걷어내면 offset이 곧 struct member로 읽히고(여기선 offset 2 = length 필드), 트리거 조건이 값 수준으로 좁혀진다. 이것이 "폴트 사이트 → 취약 필드 → 트리거 값"으로 이어지는 RCA의 마지막 연결이다.

그런데 여기 이 장 전체의 함정이 있다. 리듀서의 오라클을 단순히 "크래시하면 통과"로 두면, 축소는 최소 입력이 아니라 **가장 쉽게 도달하는 아무 크래시**로 수렴한다. 파서에 결함이 둘 이상이면(대개 그렇다) 원래 잡으려던 OOB가 아니라, 우연히 더 얕은 NULL 역참조로 갈아탄 입력을 손에 쥐게 된다. `afl-tmin`은 크래시 입력을 크래시 유지한 채 줄이지만, 기본값은 크래시의 "모양"에 어느 정도 관용을 두어 다른 폴트로 새어갈 수 있고, `AFL_TMIN_EXACT=1`을 줘야 같은 위치의 크래시만 인정한다. `Reported` 그래서 불변량을 "크래시한다"가 아니라 "**같은 폴트 사이트에서** 크래시한다"로 못 박아야 한다. 오라클이 스택 시그니처(또는 크래시 PC)를 비교하지 않으면, 그 축소 결과는 원래 버그의 최소 재현이 아니다.

두 번째 전제는 **결정론**이다. `ddmin`도 `afl-tmin`도 오라클을 수백 번 호출하며 이분한다. 오라클이 flaky하면 — 레이스로 터졌다 안 터졌다 하거나, ASLR 배치나 초기화되지 않은 메모리 값에 크래시가 종속되면 — 리듀서는 "이 부분을 빼면 통과"라고 잘못 판정하고 결함 바이트를 지워 버린다. 완화책은 오라클 안에서 N회 반복 실행해 "한 번이라도 같은 폴트로 터지면 실패"로 처리하고, ASLR을 끄고(`setarch -R`), ASan/결정론적 할당자로 재현성을 끌어올리는 것이다. `Inferred` 레이스성 결함(3부 14장)은 애초에 이 방식으로는 잘 안 줄어든다 — 축소 전에 결정론화가 먼저다.

## 버전 차이와 한계

- **입력 리듀서 vs 소스 리듀서**를 헷갈리지 말 것. `afl-tmin`·`ddmin`은 *파서에 먹이는 입력*을 줄인다. `creduce`(C-Reduce)·`llvm-reduce`는 *소스 코드*를 줄인다 — 컴파일러/툴체인 버그나 "이 소스가 왜 이 진단을 내나"를 좁힐 때 쓰고, 축소 중에도 유효한 프로그램을 유지하며 "interestingness test"로 판정한다. `Reported` 대상이 파서 입력이면 전자, 컴파일러/소스면 후자다.
- `afl-tmin`의 결과는 하네스와 계측 방식에 종속된다. 커버리지 기반 최소화(`-e`, edge 전용)와 크래시 최소화는 목적이 다르다 — 크래시를 줄일 땐 크래시 모드로 돌려야 하고, 커버리지 최소화 결과를 크래시 최소화로 착각하면 안 된다. `Reported`(플래그 의미는 사용 중인 AFL++ 버전 문서 재확인 필요)
- 최소 입력은 **국소 최소**다. 사람이 눈으로 더 줄일 수 있는 경우가 흔하다(구조를 알면 필드 단위로 손질). 자동 축소 뒤 수동 정리를 한 단계 더 거치면 재현물이 더 깨끗해진다.
- 에뮬레이터/호스트 하네스에서 줄인 입력이 AVD 앱에서도 같은 폴트를 내는지 마지막에 한 번 대조한다. 할당자·ABI 차이로 폴트 사이트가 미세하게 달라질 수 있다.

## 정리

- 입력 축소는 미학이 아니라 RCA다 — 잡음을 걷어내면 offset이 struct member로, 값이 트리거 조건으로 읽힌다.
- 불변량은 "크래시한다"가 아니라 "같은 폴트 사이트에서 크래시한다". `AFL_TMIN_EXACT` 없이 돌린 결과는 다른 버그의 최소 재현일 수 있다.
- 축소는 결정론적 오라클을 전제로 한다. 레이스·ASLR·uninit 종속 크래시는 축소 전에 결정론화가 먼저다.
- 1-minimal은 국소 최소일 뿐 전역 최소가 아니다 — 자동 축소 뒤 수동 정리 한 단계.

**점검 질문** — (1) `afl-tmin`을 그냥 돌린 최소 입력이 원래 버그의 최소 재현이 아닐 수 있는 이유는? (2) 레이스로 터지는 크래시를 `ddmin`으로 바로 줄이면 무엇이 깨지는가? (3) `afl-tmin`과 `creduce`는 각각 무엇을 줄이며, 언제 어느 쪽을 쓰나?
