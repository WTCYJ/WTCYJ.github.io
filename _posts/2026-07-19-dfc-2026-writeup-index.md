> **이 시리즈는** DFC 2026 에 2인 팀으로 참가하며 작성한 분석 제출본을, 블로그용으로 다시 정리한 열 편의 기록이다. 각 글은 독립적으로 읽을 수 있다.

## 왜 열 편으로 나눴나

문제마다 증거의 **형태 자체**가 다르다. EVTX 두 개, 컨테이너 이미지 tar, 안드로이드 기기 이미지, VMware suspend 상태, 온체인 원장, CloudTrail JSON, CRIU 체크포인트, 7z 아카이브, 프론트엔드 JS 번들. 공통 워크플로가 없다시피 해서 하나의 글로 묶으면 각 문제의 판단 지점이 뭉개진다.

대신 반복해서 나온 함정은 있다. 그 얘기부터.

## 열 편에서 반복된 것

**① 이름이 아니라 관계를 본다.**
101 에서는 레지스트리 값 이름이 아니라 **그 값을 쓴 PID** 가 미끼와 진짜를 갈랐다. 201 에서는 `postmaster` 라는 정규 프로세스명 위장이 **PID 1 의 자식으로 붙은 프로세스 트리** 앞에서 무너졌다. 102 에서는 서비스 이름이 전부 정상 Windows 구성요소를 사칭하고 있어서, 판단 기준이 **실행 경로와 부모 프로세스**로 옮겨 갔다.

**② 부재도 증거다.**
103 에서 메모리 덤프에 `manji` 문자열이 0건이라는 사실이 "이건 다른 프로세스의 덤프" 를 확정했다. 201 에서 PostgreSQL 메모리에 `47.243.x` 가 0건이라는 사실이 C2 와 채굴 풀을 분리했다. 104 에서는 `referenceBlobs: []` 라는 빈 배열 하나가 강한 정황을 "미확인" 으로 되돌렸다.

**③ 로그 필드를 그대로 믿지 않는다.**
102 에서 Sysmon Hash 필드는 악성 파일뿐 아니라 **정상 `cmd.exe` 에 대해서도** 69초 만에 다른 MD5 를 기록했다. 해시 IOC 를 단독으로 썼다면 정반대 결론이 나왔다. 153 에서는 GuardDuty 알림 11건 중 7건이 오탐이었고, 가장 이른 "악성 IP" 는 정상 컴플라이언스 스캐너였다.

**④ 집계 기준을 먼저 못 박는다.**
152 와 251 은 살아 있는 온체인 데이터라 조회할 때마다 숫자가 변한다. 사건 구간을 고정하지 않으면 보고서가 재현되지 않는다. 153 에서는 S3 GET 요청 수가 아니라 **HTTP 200 응답 수** 로 세야 실제 유출 규모가 나왔다.

**⑤ 결론을 데이터가 허용하는 지점에서 끊는다.**
102 의 내부 확산은 "시도 확인, 성공 미확정" 이고, `VV511.EXE` 는 본문이 데이터셋에 없어 악성이라 쓸 수 없었다. 103 의 C&C 포트는 "못 찾음" 이 아니라 "바이너리에 없음" 이었다. 104 는 정황이 아무리 강해도 첨부 증거가 없으면 첨부라 쓸 수 없다.

## 100번대 — 침해사고 분석

### [101 · Ghost in the Shell](/posts/dfc-2026-101-ghost-in-the-shell/)
EVTX 두 개로 파일리스 3단계 PowerShell 로더를 복원한다. 레지스트리가 지속성이 아니라 **단계 간 데이터 전달 통로**로 쓰였고, 같은 키 아래 미끼 값이 여덟 개 넘게 깔려 있었다. Base64 조각을 "붙인 다음 디코딩" 해야 하는 순서 함정이 마지막 관문.

### [102 · Masquerade](/posts/dfc-2026-102-masquerade/)
RDP 침투 → IIS 워커의 실행 파일 기동 → WMI·Speech·FontCache 를 사칭한 서비스 셋 → 내부망 스캔. 여기서 **Sysmon Hash 필드가 실제 파일과 불일치**하는 것을 확인하고, 신뢰 가능한 IOC 와 단독 신뢰 금지 IOC 를 나눠 정리했다.

### [103 · What's in my container?](/posts/dfc-2026-103-whats-in-my-container/)
이미지 레이어 목록과 컨테이너 export 목록의 **차집합** 으로 런타임 투입 봇넷을 한 번에 찾는다. 정상 빌드 13개월 뒤에 붙은 레이어가 시크릿을 평문 ENV 로 심었다. C&C 포트를 문자열·디스어셈블·메모리 세 방향으로 확인하고 "고정 포트 없음" 으로 확정.

### [104 · Every Edit Tells a Story](/posts/dfc-2026-104-every-edit-tells-a-story/)
안드로이드 아티팩트로 AI 생성 영상의 출처를 되짚는다. WebView HTTP 캐시에서 프롬프트·모델·시드를 복원하고, 브라우저 History DB 와 reading list MHTML 로 사전 수집 경로를 재구성했다. 그리고 `referenceBlobs: []` 앞에서 결론을 끊었다.

## 150번대 — 암호·자산 추적

### [151 · Pull the Plug?](/posts/dfc-2026-151-pull-the-plug/)
패스프레이즈 없이 LUKS2 컨테이너를 연다. VM 이 suspend 상태라 `.vmem` 이 남았고, **AES-256 키 스케줄이 자기 자신으로 검증되는 성질** 을 이용해 메모리를 스캔했다. 후보 11개 → ext4 매직으로 1개 → LUKS2 PBKDF2 digest 로 증명.

### [152 · Mnemonic Yum](/posts/dfc-2026-152-mnemonic-yum/)
SNS 에 공개된 12단어 니모닉이 함정인 이유. 공개 키의 서명 weight 는 1, 계정 threshold 는 3 이다. 조회는 되고 출금은 안 되며, 가스비로 넣은 TRX 는 중앙값 57초 만에 쓸려 나간다. `getapprovedlist` 로 실제 서명자를 확인해 입증했다.

### [153 · Operation Cloud Harvest](/posts/dfc-2026-153-operation-cloud-harvest/)
CloudTrail 11,562건에서 진짜 침해만 골라낸다. GuardDuty 알림 11건 중 7건이 오탐이고, 가장 이른 알림은 `userAgent: compliance-scanner` 였다. S3·CloudTrail·Route 53·VPC Flow 네 로그가 서로를 검증하는 구조.

## 200번대 이상 — 컨테이너·웹·온체인

### [201 · Who stole my Honeypot?](/posts/dfc-2026-201-who-stole-my-honeypot/)
쿠버네티스 Pod 의 CRIU 체크포인트 하나가 증거의 전부. `pstree.img` 를 protobuf 로 직접 파싱해 프로세스 트리를 세우고, `pages-1.img` 에서 `COPY … FROM PROGRAM` 으로 실행된 셸 스크립트와 랜섬 노트를 꺼냈다. 마이너는 `pg_wal` 안에 숨어 있었다.

### [202 · Toy Story](/posts/dfc-2026-202-toy-story/)
`eval(expr, {'__builtins__': {}}, {})` 이 방어가 아닌 이유를 사건으로 확인한다. `__subclasses__()` 로 `Popen` 을, `BuiltinImporter` 로 `nt` 모듈을 손에 넣는 2단계 우회. 시스템 타임존(PDT)과 `datetime.utcnow()` 가 섞여 7시간 어긋나는 타임라인 보정도 여기에.

### [251 · Carpet Pull](/posts/dfc-2026-251-carpet-pull/)
사용자 접점 주소의 런타임 바이트코드가 800바이트뿐이었다. 스테이킹 컨트랙트가 아니라 `upgradeTo` + `delegatecall` 프록시. 감사받은 V1 으로 예치금을 모은 뒤 숨겨진 인출 함수가 박힌 V2 로 교체하는 구조이고, 악성 구현체는 교체 3분 전에 이미 배포돼 있었다.

## 표기와 범위에 대해

- 각 글은 제출본을 블로그용으로 재정리한 것으로, **분석 절차·아티팩트 경로·수치는 원본 그대로**다.
- 104 번 문제에 등장하는 SNS 계정 식별자는 제3자 보호를 위해 대체 표기했다.
- 152·251 의 자산은 각각 Nile TRON 테스트넷과 Ethereum Sepolia 테스트넷 자산으로, **실제 금전 가치가 없다.**
- 팀 참가였지만 팀원 개인정보는 표기하지 않았다.
