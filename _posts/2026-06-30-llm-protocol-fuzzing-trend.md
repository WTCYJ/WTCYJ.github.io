## 초록

본고는 상태 기반 네트워크 프로토콜 퍼징과 대규모 언어 모델(large language model, LLM) 기반 입력 생성이라는 두 갈래의 연구가 ChatAFL[3]에서 수렴하는 과정을 계보적으로 검토한다. 본 검토가 견지하는 논지는 다음과 같다. 프로토콜 퍼징에서 입력 생성에 요구되는 *지식의 출처*는 실행 관측(execution observation)으로부터 사전학습 모델의 내재적 사전(parametric prior)으로 이행하였으며, ChatAFL이 그 이행의 결절점을 이룬다. 다만 이 이행은 탐지 성능이 아니라 *질의 비용*과 *생성 근거성(grounding)*이라는 새로운 문제 축을 부상시켰고, 두 후속 연구[4,5]는 각기 이 두 축을 겨냥한다. 이로써 해당 분야는 통합 모델의 제시 직후에 나타나는 정련(refinement) 국면에 진입한 것으로 판단된다. 본고는 중심 논문 1편, 선행 2편, 후속 2편을 대상으로 각 연구의 문제의식·기여·한계를 분석하고, 이를 관통하는 다섯 가지 동향과 향후 과제를 제시한다.

## 1. 서론

### 1.1 문제 배경

퍼징(fuzzing)은 프로그램에 대량의 변형된 입력을 주입하여 오작동을 유발하는 입력을 자동으로 탐색하는, 오늘날 가장 널리 채택되는 동적 취약점 탐지 기법이다. 현대 퍼징의 주류인 커버리지 유도(coverage-guided) 방식은 각 입력이 새로운 코드 경로를 실행하였는지를 계측하고, 새 경로를 여는 입력을 선별적으로 변이함으로써 탐색 효율을 높인다. 이때 프로그램 내부를 전면적으로 분석하지도, 완전히 배제하지도 않은 채 실행 흔적만을 관찰하는 절충 전략을 그레이박스(greybox)라 하며, 본 검토의 대상 연구는 모두 이 계열에 속한다.

파일 형식을 입력으로 받는 프로그램과 달리, 네트워크 프로토콜을 처리하는 서버는 두 가지 구조적 장벽을 부과한다. 첫째는 상태성(statefulness)이다. 프로토콜 구현은 상태 기계(state machine)로 동작하므로, 심층 코드에 도달하려면 정해진 순서의 메시지 시퀀스를 준수해야 한다. 예컨대 RTSP 서버에서 재생 처리 로직에 이르려면 `OPTIONS → DESCRIBE → SETUP → PLAY`의 순서를 온전히 통과하여야 하며, 순서를 위반한 요청은 즉시 거부된다. 둘째는 구조성(structuredness)이다. 각 메시지는 엄격한 문법을 따르므로, 비트 수준의 무작위 변이는 대부분 파서 초입에서 반려되어 심층 로직이 실행되지 못하고, 결과적으로 계측할 커버리지를 산출하지 못한다.

두 장벽은 기계 가독 명세(machine-readable specification)가 존재할 경우 상당 부분 완화된다. 그러나 실세계의 다수 구현체에는 그러한 명세가 정비되어 있지 않다. 따라서 본 분야의 핵심 물음은 "명세가 부재한 환경에서 순서와 문법에 관한 지식을 어디에서 확보할 것인가"로 수렴한다. 본고의 서술 축은 이 물음에 대한 응답이 *관측 → LLM의 내재 지식 → 외부 문서·취약점 지식*으로 이동해 온 궤적이며, 이 "지식 출처의 이행"이 다섯 연구를 하나의 계보로 결속한다.

### 1.2 본고의 구성

2절에서는 상태 기반 퍼징과 LLM 기반 퍼징의 시원에 해당하는 두 선행 연구를, 3절에서는 이들을 결합한 중심 연구 ChatAFL을, 4절에서는 그 한계를 분화적으로 해소한 두 후속 연구를 분석한다. 5절은 다섯 연구를 대조·종합하고, 6절과 7절에서 동향과 향후 과제를 논의한다.

## 2. 선행 연구

### 2.1 AFLNet[1]: 관측 기반 상태 추론

Pham 등[1]은 상태 기반 프로토콜 구현을 대상으로 한 최초의 커버리지 유도 그레이박스 퍼저를 제안하였다. 본 연구의 설계는 세 축으로 요약된다. 첫째, 실제 클라이언트–서버 교신 기록(packet capture)을 시드로 활용함으로써 명세 의존성을 제거한다. 둘째, 입력을 메시지 단위로 구조화하여 메시지 수준의 변이 연산을 적용한다. 셋째, 서버의 응답 코드를 상태의 대리 표지로 삼아 상태 기계를 역추론하고, 이를 변이 우선순위 결정에 반영한다.

AFLNet의 가장 본질적인 기여는 알고리즘적 정교함이 아니라 문제의 재정의에 있다. 즉 "명세의 부재"를 극복 불가능한 제약으로 두는 대신, *관측된 행동으로부터 상태를 학습한다*는 연구 질문으로 전환함으로써 이후 연구의 준거점을 마련하였다. 그러나 본 기법은 시드 코퍼스에 존재하지 않는 새로운 구조의 메시지를 합성하지 못하여 구조의 장벽을 해소하지 못하며, 응답 코드에 근거한 상태 추상화의 해상도가 제한적이고, 커버리지 정체(plateau)를 능동적으로 이탈할 기제를 결여한다. 이 세 한계는 이후 ChatAFL이 겨냥하는 지점으로 남는다.

### 2.2 TitanFuzz[2]: 언어 모델의 입력 생성기화

Deng 등[2]은 LLM을 퍼징의 입력 생성기로 직접 활용한 최초의 연구를 제시하였다. 방대한 코드·문서를 사전학습한 언어 모델의 특성에 착안하여, 생성형 모델(Codex)로 유효한 입력 프로그램을 산출하고 채움형(infilling) 모델(InCoder)로 이를 변이한다. 저자는 딥러닝 라이브러리를 대상으로 TensorFlow와 PyTorch에서 각각 30.38%, 50.84%의 코드 커버리지 향상과 65건의 결함(신규 44건)을 보고하였다.

본 연구의 통찰은 "언어 모델은 입력의 구조를 이미 내재적으로 학습하고 있으며, 따라서 명세 부재 환경에서 문법 지식을 제공하는 사전(prior)으로 기능할 수 있다"는 한 명제로 압축된다. 다만 본 기법은 독립적 입력을 단발적으로 생성할 뿐 메시지 간 순서, 즉 상태 시퀀스의 개념을 결여하므로 상태의 장벽에 대응하지 못하며, 적용 대상 또한 파이썬 API 호출로 한정된다.

요컨대 두 선행 연구는 상보적 관계에 있다. AFLNet은 상태를 다루되 구조를 다루지 못하고, TitanFuzz는 구조를 다루되 상태를 다루지 못한다. 두 결손이 정확히 대칭을 이룬다는 점에서, 양자의 결합 가능성은 이 시점에 이미 잠재되어 있었다고 평가할 수 있다.

## 3. 중심 연구: ChatAFL[3]

Meng 등[3]의 ChatAFL은 명세가 부재한 프로토콜 구현에서 상태와 구조의 두 장벽을 동시에 넘는 것을 목표로 한다. 채택된 전략은 명료하다. AFLNet의 상태 피드백 골격을 유지한 채, 그 위에 TitanFuzz가 제시한 LLM 기반 지식을 이식하는 것이다.

본 연구의 설계적 특징은 증축이 아니라 절제에 있다. 퍼징 루프 자체를 재설계하지 않고, AFLNet이 진전하지 못하는 세 지점에서만 언어 모델에 질의한다. 그 결과 두 구성 요소의 역할이 분리된다. 퍼저는 입력을 실제로 송신하고 커버리지를 계측하는 실행·피드백 엔진으로, 언어 모델은 정체 국면에서 무엇을 시도할지를 조언하는 지식·계획 엔진으로 기능한다. 이 분업 구조는 이후 모든 후속 연구가 계승하는 설계 원형으로 자리 잡는다.

세 개의 개입 지점은 다음과 같이 각기 상이한 장벽에 대응한다. 첫째, *문법 구성(grammar construction)*은 메시지 타입별 문법을 언어 모델로 추출하여 문법을 보존하는 변이를 수행함으로써 구조의 장벽을 겨냥한다. 둘째, *시드 다양화(seed enrichment)*는 기록된 시퀀스에 부재하던 메시지 유형을 언어 모델로 보강하여 초기 시드의 빈곤을 완화한다. 셋째, *시퀀스 예측(sequence prediction)*은 커버리지 정체 시 후속 메시지와 상태 전이를 언어 모델로 예측하여 상태의 장벽, 즉 심층 상태 도달과 정체 이탈을 겨냥한다.

표준 벤치마크 ProFuzzBench에서 AFLNet 및 NSFuzz와 비교한 평가 결과는 다음과 같다.

| 지표 | vs AFLNet | vs NSFuzz |
|------|-----------|-----------|
| 상태 전이 수 | +47.6% | +42.7% |
| 발견 상태 수 | +29.6% | +25.8% |
| 코드 커버리지 | +5.8% | +6.7% |
| 신규 취약점 | 9건 | (각각 3건, 4건) |

이 수치의 해석에는 신중을 요한다. 코드 커버리지 향상은 +5.8%에 그쳐, 이 지표만으로는 점진적 개선으로 오독될 소지가 있다. 그러나 상태 전이 +47.6%와 신규 취약점 9건을 함께 고려하면, ChatAFL의 기여가 "기존 코드를 더 넓게 덮은 것"이 아니라 "기존 기법으로는 도달 불가능하던 상태 공간을 개방한 것"에 있음이 드러난다. 이는 어떤 지표를 전면에 두느냐가 무엇을 기여로 인정할지를 규정한다는 점을 보여 주는 사례로서, 본 분야의 평가 관행을 이해하는 데 시사하는 바가 크다.

한편 저자와 후속 연구가 지적하는 본 연구의 한계는 네 가지다. 언어 모델의 환각(hallucination), 대상 프로토콜에 대한 모델의 사전 지식을 전제하는 지식 가정, 질의마다 누적되는 토큰 비용, 그리고 단발 프롬프트 출력에 대한 의존이 그것이다. 후술하듯 이 한계 목록은 이후 약 1년간의 후속 연구가 다루는 사실상의 연구 의제로 기능한다.

## 4. 후속 연구

통합 모델의 제시 직후에는 그 약점을 개별적으로 공략하는 정련 연구가 분화하는 것이 통상의 양상이며, 아래 두 연구는 ChatAFL의 상이한 한계를 각각 겨냥한다.

### 4.1 MultiFuzz[4]: 근거성의 보강

MultiFuzz[4]는 환각과 지식 가정(한계 ①·②)을 겨냥한 검색 증강 기반 다중 에이전트 시스템으로, ChatAFL과 AFLNet 위에 구축된다. 첫째, 문법 추출·시드 강화·정체 이탈을 각기 전담하는 다중 에이전트로 역할을 분업한다. 둘째, 검색 증강 생성(retrieval-augmented generation, RAG)을 도입하여, RFC 규격 문서를 명제 단위로 분할·임베딩한 벡터 데이터베이스로부터 실제 규격 문장을 인출하고 이를 생성의 근거로 삼는다. 셋째, NVD의 실제 취약점(CVE) 정보를 프롬프트에 결합한다. RTSP 구현(Live555)에 대한 24시간 실험에서 ChatAFL 대비 분기 커버리지 +0.9%, 상태 전이 +2.3%(AFLNet 대비 +94.5%)가 보고되었다.

주목할 만한 점은 ChatAFL 대비 증분이 미미하다는 사실 자체다. 이는 커버리지가 이미 포화에 근접하였음을, 그리고 경쟁의 축이 "얼마나 넓게 덮는가(양)"에서 "얼마나 정확하고 신뢰할 만하게 생성하는가(질)"로 이동하였음을 시사한다.

### 4.2 ChatFuMe[5]: 질의 비용의 상각

Huang 등[5]의 ChatFuMe는 토큰 비용(한계 ③)을 겨냥한다. 저자는 ChatAFL이 테스트케이스를 하나 생성할 때마다 언어 모델을 호출함으로써 비용이 급증한다는 점을 진단하고, 패러다임의 전환을 제안한다. 즉 언어 모델에게 개별 입력이 아니라 메시지 시퀀스를 산출하는 프로그램(모델) 자체를 작성하게 하고, 이후에는 그 프로그램을 반복 실행하여 입력을 대량 생성하며, 필요 시에만 피드백으로 모델을 조정한다. 그 결과 토큰 소모는 ChatAFL의 216,596토큰/160회 호출에서 5,980토큰/16회 호출로 약 36배 절감되었으며, MQTT·Modbus·DAAP 계열 6개 구현에서 12건의 결함이 보고되었다.

본 연구의 의의는 언어 모델 질의의 입자(granularity)를 테스트케이스 단위에서 프로그램 단위로 전환함으로써 비용을 일급 평가 지표로 격상시킨 데 있다. 이는 실무 적용의 실질적 병목이 탐지 정확도가 아니라 비용과 지연이라는 인식을 반영한다.

## 5. 종합 및 논의

다섯 연구를 지식 출처와 두 장벽에 대한 대응을 기준으로 대조하면 다음과 같다.

| 연구 | 지식 출처 | 상태의 장벽 | 구조의 장벽 | 핵심 기여 |
|---|---|---|---|---|
| AFLNet | 실행 관측(pcap) | 해소 | 미해소 | 문제를 "관측 기반 상태 학습"으로 재정의 |
| TitanFuzz | LLM 사전학습 | 미해소 | 해소 | "언어 모델은 입력 구조를 내재한다"는 통찰 |
| ChatAFL | 관측 + LLM 결합 | 해소 | 해소 | 두 계보의 수렴, 상태 전이 +47.6% |
| MultiFuzz | + 외부 문서·CVE(RAG) | 해소 | 해소 | 근거성 보강(환각 억제), 미미한 증분 |
| ChatFuMe | LLM(프로그램 합성) | 해소 | 해소 | 비용 상각(약 36배 절감) |

전체 궤적은 두 독립 계보의 수렴, 통합 모델의 제시, 그리고 한계별 분화로 요약된다. 즉 상태를 다루는 AFLNet과 구조를 다루는 TitanFuzz가 ChatAFL에서 결합하여 두 장벽을 동시에 해소하였고, 그 직후 MultiFuzz와 ChatFuMe가 각각 근거성과 비용이라는 서로 다른 정련 축으로 분화하였다. 이러한 "수렴 후 분화"의 곡선은 통합 논문이 등장한 직후의 정련 국면에서 전형적으로 관찰되는 형태다.

이 계보로부터 다섯 가지 동향을 도출할 수 있다. 첫째, 지식 출처가 실행 관측에서 언어 모델의 내재 지식으로, 다시 외부 문서·취약점 지식으로 이행하였다. 둘째, 질의의 입자가 테스트케이스 단위에서 프로그램 단위로 조대화되면서 비용이 평가 지표로 가시화되었다. 셋째, 환각에 대한 대응이 단일 프롬프트에서 다중 에이전트와 검색 증강으로 정형화되며, 생성 결과를 외부 근거에 결박하는 방향이 확립되고 있다. 넷째, 후속 연구의 커버리지 증분이 중심 연구 대비 약 1%로 수렴하는 현상은 표준 벤치마크의 포화를 시사하며, 이는 퍼징 평가 방법론의 구조적 문제와 직결된다. 다섯째, 본래 변이기로 기능하던 퍼저가 실행·피드백 엔진으로, 언어 모델이 지식·계획 엔진으로 역할이 분리되었으며, ChatAFL이 이 분업의 원형을 제시하였다.

## 6. 한계와 향후 과제

본 검토가 다룬 연구들은 공통적으로 몇 가지 미해결 과제를 남긴다. 첫째, 비용 상각의 주류화가 예견된다. 실무 적용의 병목이 정확도가 아니라 비용과 지연에 있는 만큼, ChatFuMe식 프로그램 합성과 소형 로컬 모델의 증류를 결합하는 방향이 표준으로 자리 잡을 것으로 보인다. 둘째, 근거성의 폐루프화가 요청된다. 현행 검색 증강은 입력 측(규격→프롬프트)의 근거화에 머무르므로, 언어 모델이 생성한 메시지를 실제 서버 응답으로 즉시 반증하여 환각을 자동 폐기하는 출력 측 검증 기제가 후속 과제로 남는다. 셋째, 자율 에이전트형 퍼징이 부상할 여지가 있으며, 이는 산업계의 자율 취약점 발견 흐름과 합류할 잠재성을 지닌다. 넷째, 규격 문서·통신 기록·소스 코드·취약점 정보를 함께 수용하는 다중 양식(multimodal) 모델이 단일 양식의 한계를 넘어설 수 있다.

특히 시급한 과제는 벤치마크의 재정의다. 표준 벤치마크의 포화와, 사전학습 코퍼스에 대상 취약점이 이미 포함되는 시간적 데이터 누수(temporal data leakage)를 고려할 때, 미래 견고성과 비용 정규화를 반영한 새로운 평가 기준의 부재는 미미한 증분만을 보고하는 연구를 양산할 위험을 내포한다. 요컨대 본 분야에서는 지표의 개혁이 알고리즘의 개혁에 선행하여야 한다. 아울러 동일 기법이 방어 측에는 자동 결함 탐지를, 공격 측에는 자동 익스플로잇 정찰을 제공하는 이중 용도(dual-use) 위험이 상존하며, 특히 CVE 기반 근거화는 오용 시 무기화가 용이하다는 점에서 책임 있는 공개와 사용 제한이 규범으로 요구된다.

---

## 7. 결론

ChatAFL은 언어 모델을 활용한 프로토콜 퍼징의 실현 가능성을 실증하였으며, 상태 기반 퍼징과 LLM 기반 생성이라는 두 계보의 수렴점으로서 본 분야의 분기를 이룬다. 그러나 이 검토가 보인 바와 같이, 실질적 전개는 그 이후에 이루어졌다. 후속 연구는 성능이 아니라 근거성과 비용을 다투며, 이는 표준 커버리지 지표의 포화가 초래한 필연적 이행이다. 검토한 다섯 연구를 계보적으로 연결하면, 이 분야의 지향은 보다 저렴하고, 보다 신뢰할 수 있으며, 보다 자율적인 퍼징 체계로 일관되게 수렴한다.
