> 물이 한 벽의 양쪽에 같은 시각에 닿으면 그 벽은 끝까지 버틴다. 문제는 결국 "언제 닿느냐"를 영역마다 비교하는 일이다.

IOI 2007 크로아티아 대회 첫째 날 2번 문제로, 정올에는 [1025번 홍수 시뮬레이션(Flood)1](https://jungol.co.kr/problem/1025)로 올라와 있다. 시뮬레이션 문제처럼 생겼지만 좌표가 100만까지 커서 격자를 그대로 그릴 수 없다. 벽을 평면 그래프의 간선으로 보고, 물이 퍼지는 과정을 그래프 위의 거리로 옮기는 것이 풀이의 시작이다.

---

## 1. 문제

좌표평면에 점 $N$개와 벽 $W$개가 있다. 벽은 두 점을 잇는 수평 또는 수직 선분이고, 끝점에서만 닿을 수 있을 뿐 서로 겹치거나 교차하지 않는다.

시각 0에 벽으로 둘러싸이지 않은 바깥이 모두 물에 잠긴다. 그로부터 정확히 1시간 뒤, 한쪽은 물이고 다른 쪽은 마른 땅인 벽이 수압에 무너지고 물이 그 안쪽으로 들어온다. 그러면 새로 물과 땅의 경계가 된 벽이 생기고, 이 벽들도 다시 1시간 뒤에 무너진다. 무너질 벽이 더 없을 때까지 이 과정이 되풀이된다. 끝까지 남는 벽의 개수를 구하면 된다.

제약은 $2 \le N \le 100\,000$, $1 \le W \le 2N$, 좌표 $0 \le X, Y \le 1\,000\,000$ 이고 시간 제한 1초, 메모리 128MB다. 원래 IOI 문제는 남는 벽의 번호까지 한 줄씩 출력하게 하지만 정올 버전은 개수 $K$ 한 줄만 출력한다. 이 차이를 놓쳐서 처음에 IOI 형식으로 번호까지 찍었다가 오답을 받았다.

## 2. 벽이 남는 조건은 거리가 같다는 것

벽들이 평면을 여러 영역으로 나눈다. 영역마다 물이 처음 닿는 시각을 알면 각 벽이 남는지 바로 판정할 수 있다.

영역 $R$에 대해 $d(R)$을 바깥에서 $R$까지 가는 동안 건너야 하는 벽 개수의 최솟값으로 정의하자. 영역을 꼭짓점으로, 두 영역이 맞댄 벽을 간선으로 둔 그래프(쌍대 그래프)에서 바깥 꼭짓점으로부터의 최단 거리다. 바깥은 $d = 0$이다.

시각 $k$에 물에 잠겨 있는 영역의 집합을 $F_k$라 하면 다음이 성립한다.

$$F_k = \{\, R : d(R) \le k \,\}$$

$k$에 대한 귀납법으로 보인다. $k = 0$이면 바깥뿐이니 맞다. 시각 $k$에 위 집합이 잠겨 있다고 하자. 다음 1시간 동안 무너지는 벽은 한쪽이 $d \le k$, 다른 쪽이 $d > k$인 벽이다. 그런 벽 너머의 영역은 $d$가 정확히 $k+1$이고, 반대로 $d(S) = k+1$인 영역 $S$는 정의상 $d = k$인 영역과 벽 하나를 맞대고 있다. 그러니 시각 $k+1$에 새로 잠기는 영역은 정확히 $d = k+1$인 영역들이다.

벽을 사이에 둔 두 영역 $L$, $R$은 벽 하나 차이로 이어져 있으므로 거리 차가 1을 넘지 못한다.

$$\lvert d(L) - d(R) \rvert \le 1$$

$d(L) < d(R)$이면 시각 $d(L)$에 한쪽만 물이고 다른 쪽은 땅이니 그 벽은 1시간 뒤 무너진다. $d(L) = d(R)$이면 두 쪽이 같은 시각에 잠겨 물과 땅의 경계가 되는 순간이 한 번도 없다. 정리하면 벽 $e$의 양쪽 영역을 $L_e$, $R_e$라 할 때 $e$가 끝까지 남을 필요충분조건은

$$d(L_e) = d(R_e)$$

이고, 문제는 쌍대 그래프에서 BFS 한 번으로 풀린다. 예제 1의 쌍대 그래프를 그리면 다음과 같다.

이 그래프를 직접 만들 수도 있지만 꽤 번거롭다. 모든 반쪽 간선을 따라 돌며 영역을 하나하나 찾아내고, 그중 어느 것이 바깥 영역인지 가려내야 하며, 다른 도형 안에 통째로 들어 있는 연결 요소도 따로 처리해야 한다.

## 3. 바깥 테두리만 보면 되는 이유

더 가벼운 방법이 있다. 영역을 전부 찾지 않고 연결 요소의 바깥 테두리만 한 바퀴씩 돈다.

벽들이 이루는 연결 요소 하나를 $C$, 그 바깥을 감싸는 면을 $O$라 하자. $d(O) = t$라고 두면 테두리를 따라 도는 동안 만나는 벽은 두 종류뿐이다.

한쪽 면만 지나는 벽은 한쪽이 $O$, 반대쪽이 $C$ 안쪽 영역 $f$다. $f$는 $C$의 바깥 테두리에 갇혀 있으므로 물은 반드시 $O$를 먼저 거친 뒤 벽을 하나 더 넘어야 $f$에 닿는다. 그래서 $d(f) \ge t + 1$이고, $O$와 벽 하나를 맞대고 있으니 $d(f) = t + 1$이다. 거리가 다르니 무너진다.

양쪽 면을 다 지나는 벽은 양쪽이 모두 $O$다. 바깥으로 튀어나온 가지 같은 벽이 여기에 해당하고, 거리가 같으니 남는다.

판정이 끝난 테두리 벽을 지우면 $C$에서 남은 벽들은 몇 개의 작은 연결 요소로 쪼개진다. 남은 벽 중에는 $O$에 닿는 것이 없다(닿았다면 방금 테두리에서 만났을 것이다). 그래서 새 연결 요소의 바깥 면은 $d = t+1$인 영역들이 테두리 벽이 사라지며 합쳐진 공간이고, 그 테두리 벽들도 모두 $d = t+1$ 쪽에서 맞닿는다. 결국 처음과 같은 상황에서 $t$ 대신 $t+1$을 넣은 꼴이라 같은 판정을 그대로 되풀이하면 된다.

이 판정에는 $t$의 실제 값이 쓰이지 않는다. 테두리 하나 안에서는 바깥 면의 시각이 모두 같다는 사실만 있으면 된다. 덕분에 어떤 도형이 다른 도형의 어느 방 안에 몇 겹으로 들어 있는지 따질 필요가 없고, 연결 요소마다 독립적으로 테두리를 벗겨 나가면 된다.

## 4. 벽을 짚으며 걷는 규칙

남은 벽 가운데 $(x, y)$ 사전순으로 가장 작은 점 $p$에서 출발한다. 이 점보다 왼쪽이나 아래에는 남은 벽이 없으니 $p$는 반드시 바깥 면에 닿아 있고, $p$에서 뻗은 벽은 북쪽이나 동쪽뿐이다.

방향을 $0$=북, $1$=동, $2$=남, $3$=서로 번호 매기면, 진행 방향이 $d$일 때 왼쪽은 $(d+3) \bmod 4$, 직진은 $d$, 오른쪽은 $(d+1) \bmod 4$, 뒤는 $(d+2) \bmod 4$다. 바깥 면을 항상 왼편에 두고 걸으려면 갈림길마다 왼쪽, 직진, 오른쪽, 뒤 순서로 처음 벽이 있는 방향을 고른다. 출발할 때는 동쪽을 보며 $p$에 막 도착한 것으로 치면 북쪽부터 시도하게 되어 첫 걸음이 자연스럽게 바깥을 왼편에 둔다. 처음 걸었던 반쪽 간선을 다시 걷게 되는 순간이 한 바퀴의 끝이다.

그림에서 바깥으로 튀어나온 벽은 올라갈 때 왼쪽 면을, 내려올 때 오른쪽 면을 지나므로 양쪽을 다 만진다. 정사각형 벽은 바깥쪽 면만 지나고, 안쪽으로 뻗은 가지는 아예 지나지 않는다. 정사각형이 지워진 다음 바퀴에서 이 가지는 홀로 남은 선분이 되어 양쪽 면을 다 지나게 되고, 실제로도 양쪽이 모두 정사각형 안쪽 공간이라 남는 벽이 맞다.

처음 짤 때는 이 우선순위를 거꾸로, 오른쪽부터 시도하게 짰다. 예제는 그대로 통과했는데 칸 단위 0-1 BFS 브루트포스와 무작위로 대조해 보니 금방 어긋나는 입력이 나왔다. 오른쪽부터 고르면 바깥 면이 오른편으로 가서 그림의 2, 3번처럼 바깥으로 튀어나온 가지를 건너뛰고 안쪽으로 파고든다. 테두리를 도는 방향과 갈림길 우선순위는 반드시 짝이 맞아야 한다.

한 바퀴 동안 각 반쪽 간선은 많아야 한 번 지나고, 지난 벽은 바로 지우므로 벽 하나는 전체를 통틀어 두 번 넘게 걷히지 않는다. 시작점을 고르는 정렬을 빼면 $O(N + W)$다.

## 5. 코드

정올에서 112ms로 통과한 코드다. 알고리즘은 4절 그대로이고, 입출력과 자료구조는 평범하게 짰다.

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    int n; scanf("%d", &n);
    vector<int> X(n), Y(n);
    for (int i = 0; i < n; i++) scanf("%d %d", &X[i], &Y[i]);
    int w; scanf("%d", &w);
    vector<array<int, 4>> adj(n);
    for (auto& a : adj) a.fill(-1);
    vector<int> A(w), B(w);
    for (int i = 0; i < w; i++) {
        scanf("%d %d", &A[i], &B[i]); A[i]--; B[i]--;
        int a = A[i], b = B[i], d;
        if (X[a] == X[b]) d = Y[b] > Y[a] ? 0 : 2;
        else d = X[b] > X[a] ? 1 : 3;
        adj[a][d] = i; adj[b][(d + 2) % 4] = i;
    }

    vector<int> ord(n);
    iota(ord.begin(), ord.end(), 0);
    sort(ord.begin(), ord.end(), [&](int i, int j) { return X[i] != X[j] ? X[i] < X[j] : Y[i] < Y[j]; });

    vector<char> alive(w, 1);
    vector<int> cnt(w, 0);
    auto hasWall = [&](int p) {
        for (int d = 0; d < 4; d++) if (adj[p][d] != -1 && alive[adj[p][d]]) return true;
        return false;
    };
    const int turns[4] = {3, 0, 1, 2};

    for (int p : ord) {
        while (hasWall(p)) {
            vector<int> touched;
            int cur = p, d = 1, sd = -1;
            while (true) {
                int nd = -1;
                for (int t : turns) {
                    int c = (d + t) % 4, e = adj[cur][c];
                    if (e != -1 && alive[e]) { nd = c; break; }
                }
                if (cur == p && nd == sd) break;
                if (sd == -1) sd = nd;
                int e = adj[cur][nd];
                if (++cnt[e] == 1) touched.push_back(e);
                cur = A[e] == cur ? B[e] : A[e];
                d = nd;
            }
            for (int e : touched) alive[e] = 0;
        }
    }

    printf("%d\n", (int)count(cnt.begin(), cnt.end(), 2));
}
```

## 6. 코드 뜯어보기

### 6.1 점 하나에 방향 네 칸

벽은 수평 아니면 수직이고 서로 겹치지 않으니 한 점에서 같은 방향으로 벽이 두 개 나갈 수 없다. 그래서 인접 리스트 대신 `adj[p][d]`에 "점 $p$에서 방향 $d$로 나간 벽의 번호"를 바로 담는다. 벽이 없으면 $-1$이다. 벽을 읽을 때 두 끝점의 좌표를 비교해 방향을 정하고, 반대쪽 끝에는 $(d+2) \bmod 4$ 칸에 같은 번호를 넣는다.

`turns[] = {3, 0, 1, 2}`가 4절의 왼쪽, 직진, 오른쪽, 뒤 순서다. 현재 방향에 이 값을 더해 $\bmod 4$를 취하면 시도할 방향이 나온다.

### 6.2 시작점과 종료 조건

`ord`는 점 번호를 $(x, y)$ 사전순으로 정렬한 것이다. 이 순서대로 점을 보면서 남은 벽이 있으면 테두리를 돈다. 앞선 점들에는 이미 남은 벽이 없으니 지금 점이 남은 벽 가운데 가장 왼쪽 아래 점이고, 그 벽은 북쪽이나 동쪽으로만 나 있다. 출발 방향 `d = 1`(동쪽)은 4절에서 말한 "동쪽을 보며 막 도착한 셈"이다.

`sd`는 첫 걸음의 방향이다. 다시 `p`에 돌아와 같은 방향으로 나가려는 순간 한 바퀴가 닫힌 것이다. 위치만 보고 멈추면 안 된다. 그림의 점 $(0, 4)$처럼 한 바퀴 안에서 같은 점을 여러 번 지나는 일이 흔하기 때문이다.

`while (hasWall(p))`로 감싸 두었지만 실제로는 점마다 많아야 한 번 돈다. `p`보다 왼쪽이나 같은 열 아래에는 남은 벽이 없으므로, `p`에서 나간 북쪽 벽의 서쪽 면과 동쪽 벽의 남쪽 면은 둘 다 바깥 면에 닿아 있다. 그래서 첫 바퀴에서 두 벽이 모두 지워진다.

### 6.3 한 바퀴에 몇 번 지났는지 세기

`cnt[e]`는 벽 `e`를 지난 횟수다. 한 바퀴 동안 같은 벽은 많아야 양쪽 면으로 한 번씩, 즉 두 번 지난다. 그래서 바퀴가 끝났을 때 `cnt[e]`가 2면 양쪽이 모두 바깥 면이라 남는 벽이고, 1이면 무너지는 벽이다.

`touched`에는 이번 바퀴에 처음 지난 벽을 모아 두었다가 바퀴가 끝나면 `alive`를 꺼서 지운다. 지운 벽은 다음 바퀴부터 갈림길에서 고려하지 않는다. 모든 벽은 언젠가 한 번은 테두리가 되어 지워지므로, 마지막에 `cnt`가 2인 벽의 개수가 곧 답이다.

벽의 반대쪽 끝점은 `A[e] == cur ? B[e] : A[e]`로 구한다.

## 8. 마치며

물이 퍼지는 과정을 쌍대 그래프의 거리로 옮기고 나면 벽이 남는 조건은 $d(L) = d(R)$ 한 줄로 줄어든다. 여기서 실제 거리 값이 필요 없다는 데까지 생각이 닿으면, 영역을 전부 구하는 대신 바깥 테두리만 한 겹씩 벗겨 나가는 풀이가 나온다.
